# Solution check

Before presenting a solution as ready to execute, check that it:

- closes the identified problem by addressing its cause;
- respects the user's constraints and agreed boundaries;
- uses existing assets where their responsibility fits;
- accounts for external evidence when that evidence matters to the decision;
- has acceptable material costs and failure modes; and
- can be verified through observable completion evidence.

Anchor consequential claims in user decisions, code, rules, or observations.
For uncertain causal claims, identify the observation that would disprove
them and use the cheapest useful check.

Compare an alternative when it could change the decision. Do not manufacture
a rejected alternative, a side effect, an ecosystem trend, or a falsifier for
an already established fact merely to fill a form. Missing relevant evidence
is a gap; an inapplicable category is not a failed gate.

If the checks support the solution, present the result, completion evidence,
and boundaries, then propose execution or continue an already authorized
handoff. If a material claim is unsupported, investigate it or ask for the
smallest user-owned decision needed. This check does not require another
approval for scope the user has already authorized.
