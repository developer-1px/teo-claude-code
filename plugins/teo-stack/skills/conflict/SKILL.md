# Conflict

서로 충돌하는 행동 뒤의 필요조건과 전제를 드러내고, 두 필요를 충족할 수 있는
대안을 찾는다. TOC의 Evaporating Cloud를 판단 도구로 사용한다.

## Cloud 구성

대화와 근거에서 다음을 찾는다.

- A: 양쪽이 실제로 공유하는 목표
- B, C: 목표를 위해 충족해야 하는 서로 다른 필요
- D, D': 각 필요를 충족한다고 주장하는 행동
- 충돌: 어떤 조건에서 두 행동을 함께 할 수 없는가

공통 목표가 없거나 자원이 실제로 배타적일 수 있다. 합류점이나 양립 가능한
해법이 반드시 존재한다고 가정하지 않는다.

관계가 도움이 되면 작은 다이어그램으로 보여준다. 확인을 위한 중간
정지 없이 가능한 분석을 마치되, 결론을 바꿀 사용자 가치 판단은 구분한다.

## 양쪽 전제 강화

각 입장을 가장 강하게 해석한다. 목표에서 필요조건으로, 필요조건에서
행동으로 가는 연결과 두 행동의 충돌에 대해 근거와 깨지는 조건을 찾는다.
상대 입장을 약하게 만들어 쉽게 이기는 주장을 구성하지 않는다.

독립 관점이 실질적인 가치를 주는 복잡한 대립이고 위임이 허용된 환경이면
옹호자 A/B를 별도 서브에이전트로 병렬 실행한다. 각자 해당 입장의 전제,
최선의 근거, 전제가 깨지는 조건을 맡고 메인이 종합한다.
간단한 문제이거나 위임이 불가능하면 메인이 두 관점을 구분해 검토하며,
실제로 실행하지 않은 에이전트 결과를 주장하지 않는다.

## 대안과 판단

우선 행동이 유일하다는 전제, 다음으로 양립 불가 조건, 마지막으로
필요조건 자체를 검토한다. 그 순서가 맞지 않으면 근거에 따라 조정한다.

돌파구가 있으면 어떤 전제가 달라지는지와 필요한 실제 변경을 설명한다.
B와 C가 모두 충족되는지, 새 비용이나 충돌이 감당 가능한지 검토한다.
검증되지 않은 가설은 가설로 남긴다.

근거 있는 돌파구가 없으면 실제 trade-off와 선택 기준을 보고한다.
이를 숨기기 위해 억지 타협이나 "부작용 없음"을 만들지 않는다.

결과는 핵심 충돌, 양쪽의 강한 근거, 바꿀 수 있는 전제, 제안과 검증 조건으로
제시한다. 분석 자체는 구현이나 외부 조치를 승인하지 않는다.
