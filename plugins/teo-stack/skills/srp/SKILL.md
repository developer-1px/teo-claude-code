# SRP

파일의 이름, 실제 책임, 독립 변경 이유를 비교한다. 함수 수나 줄 수만으로
책임을 세거나 파일을 나누지 않는다.

리팩토링 실행에는 [코드량 기준](../doubt/SKILL.md#code-reduction)을 적용한다. 파일별 후보 LOC 하한과 전체 순증 기준은 다르다. 분리로 늘어난 import·연결 코드까지 포함하며, 각 파일만 작아졌다는 이유로 완료하지 않는다.

## 범위와 실행

분석·리뷰 요청이면 근거와 판정을 보고한다. 분리·리팩터링을 요청했거나
이미 실행을 승인했다면 그 범위에서 구현하고 검증한다. 판단이 필요하다는
이유만으로 재승인을 요구하지 않는다. 결과를 바꿀 사용자 결정이 남으면 묻는다.

## 후보 발견

지정 파일을 우선한다. 숫자가 있으면 import/export-from과 빈 줄을 제외한
LOC 하한으로 사용한다. 주석 제외가 어렵다면 계산 방법을 밝혀 포함할 수 있다.
파일도 숫자도 없으면 최근 변경 맥락을 보고, 그것도 없으면 300 LOC를
후보 발견의 기본 하한으로 쓴다.

이 값은 완료 조건이 아니다. 한 책임을 가진 500줄 파일도 유지하며, 분리된
파일이 하한을 넘는 것도 허용한다. 빠른 선별 뒤 실제 코드를 읽어 판단한다.

## 책임 판정

각 후보에서 다음을 확인한다.

- 파일명이 드러내는 목적과 실제 동작, 근거 위치
- 독립적으로 변경될 이유와 그것을 소유하는 코드
- 분리 후 남을 의존 방향, caller knowledge, 순환 위험
- 관련 테스트·스타일·타입을 함께 옮겼을 때의 locality

책임이 하나면 유지한다. 독립 변경 이유가 둘 이상이고 분리 후 locality가
유지되거나 좋아질 때 나눈다. 서로의 내부를 계속 알아야 하거나 함께 열어야
이해된다면 하나의 deep module로 유지하거나 내부 구조만 정리한다.

불확실한 후보는 빠진 증거와 다음 확인을 보고한다. 분석 결과를 기록하려고
자동으로 FIXME 주석을 넣지 않는다.

## 구현과 완료

분리할 책임, 목적지, 원본에 남을 역할, import·public contract 영향을
구체화한 뒤 옮긴다. 복잡한 이동은 표나 트리로 설명하고, 작은 변경에는
고정 서식을 요구하지 않는다.

책임과 함께 움직여야 하는 테스트·스타일·타입도 함께 다룬다. 파일명과
주 export의 관계는 저장소 관례를 따르며, 실제 외부 계약은 보존한다.
내부 import 경로를 유지하려고 불필요한 facade를 만들지 않는다.

영향받은 동작과 import 경계, 저장소 필수 검사를 검증한다. 판정과 근거,
변경한 책임 경계, 실행한 검사, 남은 불확실성을 보고한다.
